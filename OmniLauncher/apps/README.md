# OmniLauncher apps — shell and UI

Two thin layers over `../crates/omni-core`. Neither contains launcher logic; both are
adapters. The contract they implement is **[`../COMMANDS.md`](../COMMANDS.md)**.

```
apps/launcher-shell   Tauri 2 (Rust): command registration, event bridge, window
apps/launcher-ui      Vue 3 + TypeScript + Tailwind: rendering only
```

## Prerequisites

| Requirement | Notes |
|---|---|
| Rust 1.96+ | Workspace toolchain |
| Node 20+ / npm | Verified on Node 25.6.0, npm 11.8.0 |
| WebView2 runtime | Preinstalled on Windows 11; Tauri does not bundle a browser |
| `tauri-cli` | Only for `dev`/`bundle`: `cargo install tauri-cli --version "^2"` |

## Working on it

```powershell
# From OmniLauncher/apps/launcher-ui — UI alone (no Rust, mock-free but core-less):
npm install
npm run dev            # http://localhost:5173 — commands reject without the shell
npm run build          # strict vue-tsc typecheck + production bundle

# From OmniLauncher/apps/launcher-shell — the real app:
cargo tauri dev        # builds the UI, opens the window, hot-reloads the web layer
cargo tauri build      # produces the MSI/NSIS installer

# Compile-only checks (what CI and the SOUL gate run):
cargo build -p launcher-shell
cargo clippy --workspace --all-targets
```

`cargo build -p launcher-shell` compiles the shell without needing `tauri-cli`, because
`tauri.conf.json` points `frontendDist` at `../launcher-ui/dist` — build the UI first, or
the bundle step has nothing to embed.

## Layout

```
launcher-shell/
  src/lib.rs           run(): builder, state, startup duties (job recovery)
  src/commands.rs      one #[tauri::command] per AppService method — no decisions
  src/events.rs        WindowSink: CoreEvent -> Tauri event, verbatim
  tauri.conf.json      window, CSP, bundle
  capabilities/        least-privilege permissions for the web layer
  icons/               icon.png / icon.ico (generated deterministically; see below)

launcher-ui/
  src/api/types.ts     TypeScript transcription of the Rust DTOs + events
  src/api/index.ts     the ONLY module that calls invoke()/listen()
  src/store.ts         reactive cache — refilled by events, never patched locally
  src/App.vue          navigation between the six surfaces + toast rail
  src/views/           InstancesView, AccountsView, JobsView, ImportView,
                       ConsoleView, SettingsView (ARCHITECTURE §7)
```

## Why there are no tests in these directories

ARCHITECTURE §8: *"UI: command/event contract tests; no logic to test in the shell by
design."* Those tests live in `omni-core/tests/app.rs`, where they run headlessly against
the same `AppService` the shell dispatches into. Testing at that layer covers the
behavior; testing the shell would only re-test Tauri's own dispatch.

The UI's guard is the compiler: `npm run build` runs `vue-tsc` in strict mode with
`noUnusedLocals` and `noUnusedParameters`, so the TypeScript transcription of the contract
cannot rot silently.

## Icons

`icons/icon.png` and `icons/icon.ico` are placeholder brand art generated by the scripts
recorded in the brick-7 commit message — deterministic, dependency-free, and regenerable
rather than opaque binaries. Replace them with final artwork when branding is ready;
nothing depends on their content beyond `tauri.conf.json`.

## Compliance notes (not optional)

- The Mojang disclaimer in `App.vue`'s sidebar and `SettingsView.vue` is required on all
  materials (COMPLIANCE §1). Do not remove it while restyling.
- The server EULA panel in `InstancesView.vue` is the **only** path to
  `accept_server_eula`. It must stay an explicit, deliberate user action (D8) — never a
  checkbox pre-ticked, never implied by pressing Launch.
- The account surface must never render a password field. Sign-in happens on Microsoft's
  page; the launcher only displays a device code (COMPLIANCE §2).
